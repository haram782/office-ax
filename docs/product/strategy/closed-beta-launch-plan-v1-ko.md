# Office-AX 클로즈드 베타 런칭 계획 v1

문서 상태: MVP 마감과 첫 외부 공개(클로즈드 베타)의 기준 문서. MVP 전체 범위는 `mvp-scope-and-gap-v1-ko.md`를 전제로 하며, 이 문서는 그 다음 묶음을 정의한다.

작성 배경: 2026-07-04 그릴링 세션(계획 스트레스 테스트 인터뷰)에서 19개 결정을 확정하고 8개의 숨은 갭을 발견하여 해소했다.

## 1. 한 줄 정의

5개 포맷(XLSX/PDF/HWP/DOCX/PPTX)의 현재 깊이 E2E를 다듬어 MVP를 마감하고, 공공·행정 인접 직군 지인 5~20명에게 초대제 클로즈드 베타를 열어, 사용 1~2주 후 심층 인터뷰로 다음 라운드의 방향을 결정한다.

## 3. 그릴링에서 발견·해소한 갭

구현·기획 문서 어디에도 없던 항목들. 리스크 관리 차원에서 기록한다.

1. **배포 부재**: 앱용 Dockerfile·배포 설정이 레포에 전무했고 기획 문서에도 배포 항목이 없었다. → M2에서 신규 작성
2. **OAuth-터널 비양립**: 가변 URL 터널로는 Google OAuth가 동작하지 않는다. → 무료 고정 호스트네임 터널로 해소
3. **게스트 인증 붕괴**: 프론트에 하드코딩된 공유 토큰 2개가 인증의 실체였다. → OAuth + allowlist로 대체, 토큰 제거
4. **마스킹 커버리지 구멍**: `mask_pii`가 analyze_document에만 적용되어 채팅·PatchPlan 경로는 원문이 LLM API로 전송 중이었다. → text_chat 마스킹 추가 + 고지
5. **dev = prod 머신 충돌**: 같은 맥·같은 DB에서 개발과 베타 서빙이 겹쳐 마이그레이션 사고·재시작 유실 위험. → 스택 분리 + 배포 창
6. **OCR 미구현**: 스캔 PDF는 `pdf_image`로 판별까지 되지만 OCR 파서가 뼈대 코드라 추출이 실패한다. 행정 직군은 스캔본 비율이 높다. → 베타 제외 + 업로드 시 정직한 안내 문구, 수요는 인터뷰로 확인
7. **HWP 실물 미검증**: 자동 테스트는 합성 파일 기준. 실제 행정 HWP(복잡한 표, 버전별 차이)로 검증한 적 없음. → M3 선행 태스크 1번으로 실물 5~10개 선확보 검증
8. **보존 정책-베타 기간 충돌**: 30일 자동 삭제가 4~6주 베타와 겹침. → 고지 문구로 해소 (결정 15)

M1 구현 리뷰(2026-07-05)에서 추가 발견·처리:

9. **스캔본 크레딧 차감**: 미지원 스캔본 업로드가 DOCUMENT_ANALYSIS SUCCESS로 기록되어 크레딧을 소모하고 처리 수를 오염. → 백엔드가 source_type 기준 FAILED + error_code=unsupported_scan으로 기록하도록 수정 (크레딧 미차감 + 스캔 수요 관찰 가능)
10. **비로그인 라우트 노출**: /workspace 등이 RequireAuth 밖이라 게스트 제거 후 비로그인 접근 시 깨진 화면. → 전 사용자 페이지 라우트에 RequireAuth 적용
11. **동의 버전 재확인 갭 (수용)**: CONSENT_VERSION을 올려도 로그인 유지 중 사용자는 재동의를 받지 않음. v1 단일 문구인 베타에서는 무시하고, 고지 문구 개정 시 동의 검사를 앱 진입(RequireAuth) 레벨로 이동한다.

## 4. 구현 계획 (M1~M5)

### M1. 베타 차단 요소 해제

전부 TDD(회귀 테스트 선행) 적용. 작은 단위로 쪼갠다.

- GoogleAuthView에 `BETA_ALLOWED_EMAILS` allowlist 체크 → 미등록 이메일 403 + 안내 문구
- 프론트 Login에서 게스트 토큰 버튼 제거, 첫 로그인 시 베타 동의 화면 추가 (문구는 7절)
- 크레딧 하드 한도: 비싼 endpoint 4곳(업로드 생성·채팅 메시지·PatchPlan 생성·patch 실행) 진입 시 이번 달 UsageEvent COUNT 체크, 초과 시 429 + 프론트 안내 모달
- text_chat 태스크에 mask_pii 적용 (사용자 질문 + 문서 컨텍스트 모두 — analyze_document와 동일 정책)
- 스캔 PDF·이미지 업로드 시 "스캔 문서는 아직 지원하지 않아요" 안내 (기존 digital/image 판별 활용)

### M2. 베타 스택 인프라

- Dockerfile 2종: backend(+Node, LibreOffice, celery worker+beat), ax-engine(+LibreOffice, ax 큐 worker)
- nginx 컨테이너: 프론트 dist 서빙 + `/api`·`/media` 리버스 프록시
- `docker-compose.beta.yml`: 별도 포트·볼륨·DB. dev compose와 완전 분리. 고정 태그에서 실행
- ngrok static domain 터널 상시 실행 + Google OAuth origin 1회 등록
- Postgres 볼륨 일일 백업 스크립트, 맥 슬립 방지 설정
- 베타 반영은 야간 배포 창에만 수행

### M3. 품질 마감

- (선행) 지인에게 실제 업무 HWP 5~10개 확보 → 뷰어·분석·치환 검증, 깨지는 유형은 가이드 지원 범위 문구에 반영
- QA 체크리스트 작성·실행: 5포맷 × (업로드 → 분석 → Q&A → 수정 제안 → 적용 → 다운로드) 실파일 수동 점검 + 모바일 스모크 1회
- 발견 버그는 회귀 테스트 선행 후 수정
- 실패 문구: DocumentChange 실패 사유 → 사용자 문구 매핑 (백엔드 serializer 매핑 테이블, 프론트는 표시만)

### M4. 베타 재료

- 샘플 문서 3종: HWP 공문, XLSX 정산표, PDF 계약서
- 한 장짜리 가이드: 시작 방법, 추천 프롬프트 3개, 지원 범위(XLSX 양식 수정 정식 / 나머지 검토·텍스트 수정 / 스캔본 미지원), 30일 자동 삭제 고지, PC 사용 권장, 운영 시간 안내
- 인터뷰 질문지 (8절)
- LLM 모델 확정: 데모 시나리오 3종을 sonnet/gpt-4o로 각각 실행, PatchPlan 성공률 비교 후 env 고정

### M5. 초대 시작

- 지인 명단으로 초대 (allowlist 등록 → 링크 공유)
- 기간: 4~6주, 종료 조건 = 심층 인터뷰 5회 완료
- 보조 채널: 카톡 베타방

## 5. 운영 체크리스트

- [ ] DEBUG=False, SECRET_KEY 별도, ALLOWED_HOSTS에 터널 도메인
- [ ] `/admin/` 이 공개 인터넷에 노출됨 — 슈퍼유저 강한 비밀번호 + admin 경로 변경
- [ ] LLM provider 콘솔에서 월 지출 상한 설정 (크레딧 한도의 최후 방어선)
- [ ] Postgres 볼륨 일일 백업 확인
- [ ] 맥 슬립 방지 + 터널 프로세스 자동 재시작
- [ ] Django admin에서 UsageEvent FAILED 필터 일일 확인 (에러 관측 루틴)
- [ ] 배포는 야간 창에만, 배포 전 베타방 공지

## 6. 크레딧 정책 (베타 초기값)

```text
월 한도: 200 크레딧 (env, 사용자별 상향은 운영 판단)
차감: 문서 분석 1, PatchPlan 생성 1, 수정본 생성 1
실패한 호출: 차감 없음
초과 시: 429 + "이번 달 사용량을 모두 썼어요" 안내
```

내부 집계(토큰·비용)는 기존 UsageEvent 그대로 유지하며, 사용자 표시는 크레딧 횟수만 쓴다.

## 7. 베타 동의·고지 문구 초안

첫 로그인 시 1회 표시, 동의 후 진입.

```text
- 업로드한 문서는 AI 분석을 위해 외부 LLM API(비학습 정책 적용)로 전송됩니다.
- 채팅과 분석 단계에서는 주민번호·전화번호·계좌번호·이메일을 자동 마스킹하지만,
  문서 수정 기능은 원문 일부가 전송될 수 있습니다.
- 주민등록번호 등 민감정보가 포함된 문서는 업로드를 자제해 주세요.
- 업로드 문서는 30일 후 자동 삭제되며, 베타 종료 시 전체 삭제됩니다.
- 서비스는 베타 기간 중 예고 후 일시 중단될 수 있습니다.
```

## 8. 인터뷰 질문지 (30분, 코어 5명+)

사전 준비: 해당 사용자의 UsageEvent·업로드 이력을 훑고 들어간다.

1. 어떤 문서를 올려봤고, 원래 그 작업을 어떻게 처리하던 것이었나?
2. 가장 기대했던 작업은 무엇이었고, 결과가 기대에 얼마나 미쳤나?
3. 어디서 멈췄거나 막혔나? (이력에서 실패·이탈 지점을 짚으며)
4. HWP 문서 작업에서 "이것만 되면 쓰겠다" 싶은 한 가지는?
5. 스캔본(복사·팩스 문서)을 다루는 일이 얼마나 자주 있나?
6. 이 도구에 월 얼마라면 돈을 내겠나? 무엇이 되면 그 금액이 올라가나?
7. 동료에게 추천한다면 뭐라고 소개하겠나? 추천하지 않는다면 왜?

## 9. 완료 기준

- M1~M4 완료 후 초대 시작
- 베타 참가자 5명 이상이 업로드 → 수정본 다운로드를 1회 이상 완주
- 심층 인터뷰 5회 완료 및 기록
- 인터뷰 결과가 다음 라운드 기획(HWP 심화 vs OCR vs 과금 정책)의 입력으로 정리됨
